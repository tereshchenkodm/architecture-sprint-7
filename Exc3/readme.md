## Требования по обеспечению безопасности
**Шифрование данных**

Все данные, которые передаются между мобильным приложением и внешней платформой, должны быть защищены с помощью шифрования на основе TLS версии 1.2 или выше. Это необходимо для предотвращения их возможной компрометации и анализа.

**Обработка биометрических данных**

Биометрическая информация должна сохраняться и использоваться исключительно в зашифрованном виде, а также соответствовать действующим нормативным требованиям и стандартам безопасности.

**Сокращение объема данных**

Система должна передавать только тот объем данных, который необходим для проверки права доступа. Это снизит вероятность утечки информации.

**Мониторинг и анализ**

Необходима запись всех попыток доступа и операций пользователей, включая информацию о времени, IP-адресах и устройствах. Эти журналы должны регулярно анализироваться для выявления подозрительных действий.

**Защита от злоумышленников**

Система обязана быть устойчивой к атакам, например, подбору биометрических данных или автомобильных номеров. Это можно реализовать с помощью таких мер, как ограничение количества попыток и блокировка IP-адресов после выявленных неудачных операций.

## Методики аутентификации и авторизации
**OAuth 2.0**

Приложение должно использовать протокол OAuth 2.0 для безопасной идентификации и авторизации пользователей. Это также позволит применять внешние платформы в роли провайдеров идентификации.

**JWT (JSON Web Tokens)**

Для передачи информации о правах доступа между системами можно применять JWT, что обеспечит безопасный обмен данными и управление временем действия токена.

**Многофакторная аутентификация (MFA)**

Для функций, связанных с биометрией, рекомендуется внедрить многофакторную аутентификацию, которую пользователь проходит в момент настройки и привязки устройства к учётной записи.

**Управление доступом по ролям (RBAC)**

Система должна предусматривать модель разграничения доступа на основе ролей. Например, права собственников, арендаторов и администраторов должны различаться (например, только администратор может управлять настройками шлагбаума).

## Схема взаимодействия систем
**API-интеграция**

Интеграция между PropDevelopment и внешней платформой должна осуществляться посредством RESTful API с использованием JSON. Приложение PropDevelopment отправляет запросы для проверки и управления доступом, а внешняя платформа возвращает соответствующие ответы.

**Webhooks для получения событий**

Платформа партнёров должна поддерживать Webhooks для передачи уведомлений о событиях (например, успешное распознавание лица или номерного знака) в реальном времени. Это позволит PropDevelopment оперативно реагировать.

**Кэширование данных доступа**

Для ускорения выполнения проверки доступа система может временно хранить данные о правах доступа пользователей и номерах автомобилей с последующей регулярной синхронизацией.

Необходимо улучшить функционал мобильного приложения и бэкенда tenant-core-app для корректной работы с новым функционалом. Биометрические данные и номера, насколько я понимаю, не сохраняются системой, а только передаются в зашифрованном виде.
